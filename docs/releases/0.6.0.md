## RusTXT 0.6.0 — hardening, performance and cleanup

The GTK frontend is gone from the repository; the Iced interface introduced in 0.5.0 is the only one. Notes, undo history and settings from earlier releases are read as before, and 0.5.x can still open a database written by 0.6.0.

### Fixed

- The first visible editor line painted over the menu bar and became bold after partial redraws.
- Tab inserts a tab character instead of moving keyboard focus.
- Select-all then Delete, large pastes and Replace all in big files froze the editor for seconds to minutes (4.6 MB: 63 s); such edits now complete in about a second.
- Saving no longer silently replaces a read-only file; it is refused with a message suggesting Save As.
- Zoom changes were reverted by the configuration watcher echoing the app's own save.
- Several files failing to open at startup showed only the last error; all are listed, each named.
- An invalid theme name is reported instead of silently falling back; storage failures such as a full disk explain what they mean for unsaved drafts.
- Long tab titles are truncated on one line instead of wrapping.
- A corrupt recovery database is moved aside (`session.db.corrupt-<time>`) and the app starts with a fresh one, telling you where the old file is; previously the app refused to start.
- A snapshot failure no longer blocks typing or quitting: the error is shown once, editing continues, and a second Exit quits.

### Changed

- Undo and redo step through typed words instead of single characters.
- Cursor movement no longer rewrites the recovery snapshot; only content changes do. The app is idle when you are.
- The recovery database is created with mode `0600`, and *Discard changes and close* also deletes the note's undo history.
- Lone CR line endings are normalised to LF on load; CRLF files are still saved as CRLF.
- Files larger than 64 MiB and non-regular files (devices, FIFOs, directories) are refused with an error.
- Search results are capped at 10 000 matches ("10 000+") and the find bar no longer re-scans the document while closed.

### Removed

- The GTK frontend (`crates/rustxt-gtk`) and its documentation; the last revision containing it is tagged `v0.4.1-gtk`.
- The in-app updater. The About dialog links to the releases page; the app never downloads or replaces its own executable.

### Project

- Release pipeline hardened: actions pinned to commit SHAs, least-privilege permissions, per-platform checksums assembled into `SHA256SUMS`, build provenance attestations, an MSRV (Rust 1.88) check and `cargo deny` in CI.
- New test layers: an end-to-end regression suite for the behaviours above and golden screenshots of five UI states at 100 % and 125 %.
- `CHANGELOG.md`, `SECURITY.md`, `CONTRIBUTING.md`, `docs/configuration.md` (every setting and shortcut), issue and pull request templates.

### Downloads

| Platform | Package |
|---|---|
| Linux x86_64 | `.tar.gz` (Ubuntu 22.04/glibc 2.35 or newer), Arch `.pkg.tar.zst`, Debian 13+ `.deb`, Fedora 42+ `.rpm` |
| Windows x86_64 | Extract the Windows ZIP and run `rustxt.exe` |
| macOS Apple Silicon | Extract the `arm64-macos.zip` and move RusTXT.app to Applications |
| macOS Intel | Extract the `x86_64-macos.zip` and move RusTXT.app to Applications |

Verify downloads against `SHA256SUMS`. macOS bundles are ad-hoc signed, not Apple-notarized; if macOS blocks the app, use System Settings → Privacy & Security → Open Anyway after reviewing the source of the download. Windows executables are unsigned; the portable ZIP includes the C runtime.

If a 0.4.x GTK build is still installed, close it before starting 0.6.0: both use the same recovery database.
